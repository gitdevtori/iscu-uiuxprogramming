# 오늘뭐먹지

한식·양식·일식·분식 중 음식 종류와 매운맛 선호에 맞는 메뉴를 추천하는 서비스입니다.

- 배포: https://gitdevtori.github.io/iscu-uiuxprogramming/
- 저장소: https://github.com/gitdevtori/iscu-uiuxprogramming
- 사용 기술: HTML, CSS, JavaScript

## 11주차: 웹 접근성 개선

- 전체 색 대비를 WCAG 2.1 AA 기준(4.5:1 이상)으로 높이고, 오류·선택 상태를 문구와 기호(`✓`, `▶`, `[오류]`, `[완료]`)로 함께 표시했습니다.
- 메뉴 이미지의 대체 텍스트(`alt`)를 구체화하고, 입력 라벨·ARIA 속성·버튼/링크 이름을 기능에 맞게 명확히 정리했습니다.
- 본문 바로가기, 고대비 초점 표시(`:focus-visible`), 탭 방향키 이동, 모바일 메뉴 `Escape` 닫기를 추가했습니다.
- 제목·본문 계층(`h2 → h3 → h4`)과 안내·오류 메시지를 읽기 쉽게 보완했습니다.

### 개선 전 → 개선 후

| 항목 | 개선 전 | 개선 후 |
|---|---|---|
| 색 대비·상태 표시 | `#ff7a45` 배경·흰 글씨(2.59:1), 색상만으로 선택·오류 구분 | `#c24b1a`·`#b54517`(4.87~5.49:1)로 상향, `✓`·`▶`·`[오류]`·`[완료]` 병기 |
| 대체 텍스트·라벨 | 막연한 이미지 `alt`, 모호한 이메일 라벨·버튼명(`이전`, `다음`) | 4종 대표 메뉴가 드러나는 `alt`, 이메일 라벨·ARIA 연결 및 구체적 버튼/링크명 적용 |
| 키보드·초점 표시 | 연한 초점 그림자(`#ffd8c7`, 1.32:1), 탭 방향키·스킵 링크 없음 | 고대비 `outline`, 본문 바로가기, 탭 방향키 및 모바일 메뉴 `Esc` 닫기 추가 |
| 구조·메시지 | 빈 소개 본문, 식사 기록 카드 `h3` 중복, 불명확한 이메일 완료 문구 | 소개·기능 `<p>` 분리, 카드 `h4` 교정, 항목별 오류 및 완료 안내 명확화 |

### 확인 순서

1. `Tab` / `Shift+Tab` → 본문 바로가기·모든 메뉴·버튼·입력창 고대비 초점 확인
2. 메뉴 둘러보기 탭 → 좌우 방향키·`Home`·`End`로 탭 전환 확인
3. 추천·식사 기록 빈 값 제출 → `[오류]` 문구 표시 및 오류 항목 초점 이동 확인
4. 390px 모바일 화면 → 메뉴 열기 → `Escape`로 메뉴 닫힘 및 버튼 초점 복귀 확인

## 10주차: 메뉴 구성과 목록 필터

- 한 페이지를 3개 페이지로 나누고 `header`와 주요 메뉴 `nav`(ul·li)를 분리했습니다.
- 현재 페이지 메뉴에 `aria-current="page"`와 강조 표시를 적용했습니다.
- 768px 이하에서는 메뉴 열기·닫기 버튼으로 메뉴를 펼치고, 메뉴를 선택하면 닫힙니다.
- 식사 기록에 만족도 필터와 표시 개수·결과 없음 안내를 추가했습니다.

### 메뉴별 목적지

| 메뉴 | 목적지 | 내용 |
|---|---|---|
| 서비스 소개 | `index.html` | 소개, 주요 기능, 이용 방법 |
| 메뉴 추천받기 | `recommend.html` | 메뉴 둘러보기, 메뉴 추천·찜하기 |
| 내 기록 | `my.html` | 찜한 메뉴, 식사 기록 |

### 필터 기준

- 만족도: 전체 / 좋았어요 / 보통이에요 / 아쉬웠어요
- 기록 없음: “아직 식사 기록이 없어요.”
- 필터 결과 없음: “‘아쉬웠어요’ 기록이 없어요.”

### 확인 순서

1. 메뉴 추천받기 → 추천받기 → 찜하기
2. 내 기록 → 식사 기록 저장 → 기록 보기
3. 필터 선택 → 목록·개수 변경 확인
4. 새로고침·뒤로 가기 → 현재 위치 표시 확인
5. 모바일 화면 → 메뉴 열기 → 메뉴 선택 → 메뉴 닫힘 확인

## 9주차: 오늘의 식사 기록

- 기록 시작 → 입력 → 기록 보기의 3단계 흐름과 브라우저 저장·복원·삭제 기능을 추가했습니다.
- 만족도 라디오에서 ‘아쉬웠어요’를 선택하면 이유 입력란이 나타나고, 다른 선택에서는 숨김·비활성화됩니다.
- 실시간 글자 수 배지, 저장 시 오류 안내, 중복 제출 방지, 다시 작성·취소를 구현했습니다.
- 언더바 진행 표시, 고스트 삭제 버튼, 데스크톱 3열·모바일 2열 카드를 적용했습니다.

### 입력 조건

- 먹은 메뉴: 앞뒤 공백 제외 2~30자
- 만족도: 필수 선택
- 아쉬웠던 이유: ‘아쉬웠어요’ 선택 시 앞뒤 공백 제외 10~100자

### 확인 순서

1. 기록하기 → 빈 값·짧은 값 제출 → 오류 안내 및 수정 확인
2. 만족도 변경 → 이유 입력란 표시·숨김·비활성화 확인
3. 정상 저장 → 진행 문구·버튼 비활성화·완료 안내·목록 확인
4. 새로고침 → 기록 복원, 삭제 → 해당 기록 제거 확인
5. 다시 작성·취소 → 입력값·안내·버튼·조건부 영역 초기화 확인

## 사용자와 목적

- 사용자: 식사 메뉴를 정하기 어려운 학생·직장인
- 목표: 취향에 맞는 메뉴를 빠르게 찾아 고민 시간 줄이기
- 핵심 행동: 취향 선택 → 메뉴 추천 → 찜하기·다시 보기
- 완료 조건: 찜한 메뉴와 저장 당시 선택값 확인

## 사용자 흐름

**시작 → 취향 선택 → 선택 확인 → 추천 완료**

**중간고사: 추천 완료 → 찜하기 → 찜 목록 → 다시 보기 / 찜 해제**

이전 단계로 돌아가면 선택값을 유지하고, 다시 시작하면 현재 추천만 초기화합니다.
찜 목록은 같은 브라우저에 저장되어 새로고침하거나 다시 시작해도 유지됩니다.

## 중간고사 기능추가 시나리오

| 행동 | 이벤트 | 조건 | 화면 반응 | 다음 행동 |
|---|---|---|---|---|
| 찜하기 | click | 저장하지 않은 메뉴 | 메뉴·선택값 저장, 완료 안내 | 찜 목록 보기 |
| 같은 메뉴 추천 | click | 이미 찜한 메뉴 | 찜 버튼 비활성화 | 다시 보기 |

| 찜 해제 | click | 저장된 메뉴 | 해당 항목 제거, 개수 갱신 | 다른 메뉴 확인 / 다시 찜하기 |

| 찜하기 / 해제 | click | 저장 실패 | 목록 유지, 오류 안내 | 설정 확인 후 재시도 |
| 페이지 열기 | load | 저장 데이터 오류 | 오류 안내, 빈 목록 표시 | 메뉴 다시 찜하기 |
